# Aurora Computer Use Studio v1.5 — 中途停止诊断与视频任务进度

## 这次定位到的事实

用户提供的第三方 API 响应记录共 17 条（含一次识图预检和 16 个动作）：第 16 个动作返回的是合法的 `{"action":"keypress","keys":["down"]}`，且 `parse_status=ok`。文件中没有第 17 个动作，也没有应用层的终止原因。**不能仅凭 API 响应认定模型在第二条视频主动结束**。v1.5 新增与 API 响应同目录的 `run-*.jsonl`，逐步记录截图成功、请求发起、动作解析、动作执行开始/成功、异常类型和正常/异常终止状态（不记录 API Key、任务文本、屏幕内容）。

## 新功能

- 检测自然语言指定的抖音「第 N 个视频」（支持 1-20）；独立状态 `VideoProgress` 跟踪实际确认的序号，而不是由 VLM 反复推断计数。
- `observe_video`：模型通过截图提交该视频**稳定**的唯一性标识，只有在确实执行下一视频动作之后，再有两轮连续的相同新身份识别，才将计数从 N 变为 N+1。若只能看到变换的电影画面，无法确认独立视频，应 `ask_user`，不能随意计数。
- `done` 防提前结束：视频序号不足、PNG 尚未保存、TXT 尚未生成或文件为空时拒绝 done，并继续引导模型完成任务；重复四次无效 done 才保护性停止。
- 到达目标后锁定下刷操作，防止刷过头。
- `capture_frame`：直接调用 Windows 截图并保存原分辨率 PNG 到桌面，不需要鼠标打开截图工具。
- `write_report`：创建 UTF-8-BOM 的桌面 TXT，与 PNG 使用同一文件名前缀，避免模型打开记事本失败。**文本仅描述可见信息，单张截图无法可靠总结整段视频的音频与剧情**。
- 请求 JSON 解析失败或瞬时网络出错时，最多安全重试两次，不会执行无效返回。
- 运行日志额外生成本地生命周期记录，定位 API 响应之后是否发生截图、输入执行、程序终止异常。
- GUI 显示已确认的视频序号，步数上限可设至 200，新安装默认 60（旧用户保存的首选项不变）。

## 启动与构建

在 Windows 11 运行 `launch_win11.bat`；需要生成 EXE 时运行 `build_exe.bat`。API 配置、用户回复、响应查看器和滚动功能保留。视频任务建议将步数设置为 60-100（API 调用量和成本会随步数增加）。

## 测试任务

```
打开抖音网页版，进入可以上下切换独立视频的推荐播放流，使用播放器全屏模式。当前第一条视频记为第1条，切换到第2条后再切换到第3条，不要把视频的“第3章”计作第3条。停留在第3条，保存当前一帧 PNG 到桌面，并根据截图中可见画面和字幕生成桌面 TXT，注明无法确认的部分。最后检查两个文件均存在才结束。
```

## 如果还是突然停止

到 `%LOCALAPPDATA%\AuroraComputerStudio\api_responses\` 查找同一次任务的两个文件：

- `api-YYYY...jsonl`：模型原始响应和解析结果。
- `run-api-YYYY...jsonl`：运行事件，包含每次动作的 `execution_started`、`execution_ok`、`terminal` 或 `exception` 等标签。

如果最后只有 `execution_started` 没有 `execution_ok`，通常说明本地执行时异常或程序被终止；如果有 `execution_ok` 而没有后续 `step_begin`，应查看 `terminal` 或进程是否崩溃。只有 API 日志通常不足以确认原因。

### 安全与适用范围

第三方视觉模型会收到屏幕截图。请仅在可信、隔离的环境中使用，禁止自动执行支付、销毁文件等不可逆操作。模型识别视频身份是视觉判断，**并非可靠的抖音官方视频 ID**；若视频身份不可见，不能保证计数准确。视频或直播内容可能因页面更改、登录要求、反爬机制失效。当前环境尚未在真实 Windows 11 和用户的 deepseek-flash 接口上做端到端测试。
